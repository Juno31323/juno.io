# 1단계 검증

2026-11-12. Windows, Node 24, Astro 7.4.7, Node adapter 11, Supabase CLI 3.1, 로컬 PostgreSQL 17/Auth/Storage, Playwright + Edge에서 확인했습니다.

## 실행해 통과한 항목

- 플랫폼 타입 검사·Node 서버 빌드: 오류·경고·힌트 0건.
- DB 마이그레이션 3개 적용. 기존 테이블을 삭제하거나 공개 정책을 완화하지 않음.
- 기존 공개 자료 15건, 사진·이미지 5개 이전. 기존 블로그의 제목·원문·게시일·슬러그 일치.
- 기존 첫 사용자의 계정 소유권 연결. 새로 가입한 계정에 첫 사용자 콘텐츠가 복사되지 않음.
- 실제 로컬 가입·로그인·로그아웃, 중복 아이디 복구, 아이디 변경 방지, 비공개 기본값.
- 두 계정의 직접 Data API 요청으로 타인의 프로필·프로젝트·이미지 읽기·수정·위조 삽입 차단.
- 권한 없는 스냅샷·이전 RPC 호출 차단. 다른 소유자의 이미지 ID를 직접 넣어도 게시 차단.
- 프로필·프로젝트 저장, 실제 Storage 업로드, MIME과 다른 이미지 파일 거부, 동시 수정 충돌 시 입력 유지.
- 저장된 초안과 게시본 분리. 원본 수정 후 재게시 전에는 공개 내용이 바뀌지 않음.
- 비공개 소개가 이전 과정에서 게시되지 않는지 트랜잭션으로 검증 후 롤백.
- 한국어 키워드, 영문 기술명, 기술·역할 필터, 탐색 제외 및 탐색 상세 접근 차단.
- 13개 검색 결과의 12개/다음 1개 분할, 프로젝트·섹션 순서 저장.
- 밝기·포인트 색·섹션 표시, 실제 1280/390px iframe 미리보기.
- 링크 공개의 64자 난수 주소, 일반 OG, 검색 제외, `no-store` 응답.
- 공유 링크 재발급·비공개 전환 시 이전 본문·이미지 URL 차단.
- HTML/Markdown 스크립트·이벤트 속성·위험 링크 정제, 동일 Origin 검사.
- 공개 페이지가 JS 없이도 본문을 서버 HTML로 제공하고 이름·소개·OG를 포함함.
- 390/768/1440px에서 랜딩·공개 페이지·글·대시보드·편집·디자인·탐색의 가로 넘침 없음.
- 이전 프로젝트·연구·쿼리형 글 주소의 308 연결 및 도착 페이지 열람.
- 플랫폼의 정적 경로로 기존 개인 사진을 직접 열 수 없음.
- 기존 개인 사이트 빌드와 279개 로컬 리소스·링크 경로 검사 통과.
- 배포용 Node 서버의 공개 경로 18곳에서 폰트·CSS·JS·이미지·슬래시 경로 정상. 클라이언트 번들에 서버 키가 없음.

자동 검증은 실제 로컬 Supabase를 사용하며 운영 프로젝트에는 쓰지 않습니다. CI에는 기존 공개 자료만 담은 고정 fixture를 제공했습니다. 화면과 상세 결과는 무시되는 `artifacts/platform/`에 남습니다.

## 운영 환경이 있어야 확인할 항목

- 운영 Supabase에 새 스키마 적용, **운영 계정 UUID**로 첫 사용자 연결, 운영 이미지 전송. 현재는 별도 로컬 계정으로 흐름을 검증했습니다.
- 실제 플랫폼 서버 배포와 HTTPS 프록시·운영 Auth 이메일 발송/확인. 서버·도메인이 아직 없어 실행하지 않았습니다.
- 실제 메신저의 링크 미리보기와 `juno31323.me` 전환. 서버 HTML의 OG와 로컬 주소 연결은 확인했으며, 외부 주소 전환 전 재확인이 필요합니다.
- Docker의 Supabase 서비스는 실행했습니다. 앱 자체는 Node 빌드 서버로 검증했으며 제공한 앱 Dockerfile의 이미지 빌드는 별도 배포 검증 항목입니다.
- 실제 사용자 5명의 포트폴리오 작성·제출 사용성 조사. 테스트 계정의 결과를 실제 사용자 이용 지표로 보고하지 않습니다.

새 서버가 준비될 때까지 기존 Pages 배포·도메인·운영 DB를 유지합니다. 순서와 명령은 `README.md`, 주소 대응은 `route-map.json`을 사용합니다.
